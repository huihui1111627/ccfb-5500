# 门店边缘调度与发布平台 (edgeops)

面向连锁药店(3000+ 门店、每店一台小主机)的边缘节点容器/进程调度与发布平台。
纯 Go 标准库实现,零外部依赖。工作负载是节点上的**本地子进程**,不依赖 Docker。

## 架构

```
┌──────────────────────────────────────────────┐
│ 控制面 (cmd/controlplane)                     │
│  ├─ 调度器: 标签亲和/污点容忍/资源fit/配额      │
│  ├─  reconciler: 期望状态 vs 实际状态持续收敛   │
│  ├─ 发布编排: 试点→浸泡→分批错峰, 状态持久化    │
│  ├─ 资源推荐: 心跳指标 p95 × 1.3              │
│  └─ 控制台: 节点总览/工作负载/发布单/事件流/配额 │
└──────────────▲───────────────────────────────┘
               │ 长轮询下发期望状态 + 心跳上报(对账)
┌──────────────┴───────────────┐
│ 节点代理 (cmd/agent)          │
│  ├─ supervisor: 子进程保活/退避重启 │
│  ├─ 离线自治: 按最后期望状态运行    │
│  ├─ 日志按大小滚动, 控制面远程查看   │
│  └─ 换机: 报门店编号自动接手负载    │
└──────────────────────────────┘
```

## 需求对照

| # | 需求 | 实现 |
|---|------|------|
| 1 | 声明式 + 收敛 | `WorkloadSpec` 声明副本数/版本;`cp.Store.Reconcile` 每 500ms 对比期望与实际;控制台工作负载页展示每个副本"还差哪一步"(等待调度/等待节点上线/进程启动中/版本更新中…) |
| 2 | 调度 | `scheduler.go`: 节点剩余 CPU/内存 fit、`NodeSelector` 亲和、反亲和(同节点至多一个副本)、污点/容忍;医保服务用 `network=dedicated-line` 选择器限定专线主机;门店/区域/全局三级配额 |
| 3 | 资源推荐 | 代理心跳携带每个负载的 CPU/内存样本,控制面按 p95×1.3 给出建议值(控制台工作负载页、`/api/recommendations`) |
| 4 | 试点发布 | 发布单: 先 N 家试点门店,全部 Running 且收银流水异常计数为 0 地跑满浸泡时长(默认 24h)才进入分批全量;任何异常清零浸泡计时 |
| 5 | 离线自治 | 代理长轮询断开时 supervisor 独立保活;期望状态落盘 `desired.json`,代理重启不中断服务;恢复连接后心跳对账 |
| 6 | 日志 | 节点本地按大小滚动(默认 1MB×3);控制台节点页点"日志"经控制面代理远程查看 |
| 7 | 换机接手 | 新主机用同一门店编号注册,控制面退役旧节点并把该店全部 assignment 迁到新节点;门店数据盘(`StoreDataDir`)随机走,心跳带数据标记供校验 |
| 8 | 错峰发布 | 分批推送前检查门店营业时间,高峰窗口内的门店跳过,下个 tick 再试 |

时钟安全:发布浸泡/超时全部使用**累计 delta** 并钳制单次上限,时钟回拨不倒退、跳变不能一次跳满。

## 运行

```bash
go build ./...

# 控制面(控制台 http://127.0.0.1:8080)
./controlplane -addr 127.0.0.1:8080 -data ./cp-data

# 节点代理(每店一个)
./agent -cp 127.0.0.1:8080 -store S0001 -region 华东 \
        -listen 127.0.0.1:9000 -labels network=dedicated-line

# 混沌模拟器: 300 个节点代理, 随机断网/杀进程/时钟跳变,
# 发布中途重启控制面(发布中断), 中途更换一家店的主机,
# 结束后自动跑检查器
go run ./cmd/simulator -stores 300

# 独立检查器(对运行中的控制面)
./checker -cp http://127.0.0.1:8080 [-store S0042 -marker "store=S0042 created"]
```

检查器核对三件事:
1. **状态收敛** — 发布中断恢复后,期望状态与实际状态最终一致;
2. **换机接手** — 新节点跑齐该店全部负载,本地数据标记不变;
3. **发布规则** — 试点家数、浸泡门槛(未通过试点不得全量)、任何门店不得在营业高峰被推送。

## 目录

```
cmd/controlplane   控制面入口
cmd/agent          节点代理入口
cmd/workload       模拟业务进程(收银流水日志 + /metrics)
cmd/simulator      混沌模拟器
cmd/checker        独立检查器
internal/api       线协议类型
internal/clock     真实/模拟时钟(可加速、可跳变)
internal/cp        状态存储、调度器、发布编排、资源推荐、HTTP API、控制台
internal/agent     代理、supervisor、真实/模拟执行器、日志滚动
internal/check     收敛/发布规则/换机接手检查
internal/sim       故障注入网络 + 场景编排
```
